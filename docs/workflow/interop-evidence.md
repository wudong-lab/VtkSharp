# 互操作判断依据记录

方向、长度和所有权仍由开发者结合原生契约确认，生成器的 `ready` 不代表已证明语义安全。对本次需要人工判断的签名，把依据与最终白名单元数据一起保留，避免下次重新搜索。普通标量接口不必机械填写。

示例专用依据放在对应 `porting-notes.md`；多个示例共享的依据放在 `docs/interop/` 下的主题文档，其他文档引用它，不复制。临时候选和报告仍留在忽略目录；不要把唯一依据仅存放在临时报告中。

每条记录使用以下最小格式，代码、签名和路径保持英文：

```markdown
### <declaring-class>::<exact-signature>

- 契约：<参数方向、元素个数/单位、返回值所有权、有效期；只填写有关项>
- 依据：<VTK 版本或提交、源码仓库 URL、相对文件路径和符号；必要时包含实现文件>
- 文件 SHA256：<本地实际检查文件的哈希，用于识别源码变化>
- 决定：<采用的 whitelist 元数据或 managed 包装方式，以及理由>
- 验证：<实际运行的测试/示例及结果；未验证内容明确标出>
- 复核条件：<VTK 升级、签名/实现变化、类型映射或生命周期策略改变>
```

源码注释没有说明所有权时继续检查实现和持有者；不要把 `Get`、`Set` 或 `const` 当作归属和数组长度的证据。需要多个文件才能支持结论时记录全部相关文件。文件哈希可用以下命令取得：

```powershell
Get-FileHash -Algorithm SHA256 -LiteralPath <vtk-source-file>
```

复用记录前确认 VTK 版本、签名、元数据和相关文件哈希仍匹配；任一变化时重新检查原生契约。文件未变也不证明 ABI、编译选项或相关依赖未变。当前采用人工复核，不自动推断所有权，也不把哈希相等当作安全证明。
